# Spike 3: the abi3 wheel inside Blender

**Question.** Does a minimal `lamda-py` abi3 wheel load in Blender's bundled Python, solve on a worker thread with the GIL released, report progress to the main thread and cancel? Pass: works on Windows, macOS and Linux in Blender 5.2.

**Method.** `maturin build --release -m core/lamda-py/Cargo.toml --out addon/wheels` builds `lamda_core-0.1.0-cp311-abi3-macosx_11_0_arm64.whl` (380 KB). `tests/blender/test_wheel.py` unpacks the wheel into a temporary directory, puts it on `sys.path` (nothing is installed into Blender) and runs four checks headless:

1. Import and version.
2. The office fixture solves to the pinned seed-1 result and validates.
3. The spike-4 study kit (18,900 slots × 400 variants, generated by `lamda-cli bench-gen`) solves on a `threading.Thread` while the main thread polls `Progress.snapshot()` every 10 ms.
4. The tight study kit (8 extra pairs, backtrack budget 10⁹, so it would run for a long time) is cancelled from the main thread after 0.5 s.

Blender here: 4.3.2 with Python 3.11.9 and numpy 1.24.3, on Apple Silicon. 5.2 LTS (Python 3.13) is not installed yet.

**Numbers.**

| Check | Result |
| --- | --- |
| Import | `lamda_core 0.1.0` in Blender 4.3.2, Python 3.11.9 |
| Office fixture | solved, golden result, validator finds nothing |
| Study kit on a worker thread | solved in 0.58 s; 47 polls from the main thread saw the observation counter at 0, 299, 819, … 18,021, 18,880 |
| Cancel | outcome `cancelled` 9 ms after `cancel()`, after 987 backtracks |

The main thread polled 47 times during a 0.58 s solve, so the GIL is released for the whole solve (`py.allow_threads`), and the cancel flag is seen within one check interval (every 256 queue pops and at every observation).

**Decision.** macOS arm64 passes. The wheel targets abi3 with a 3.11 floor, so the same file is expected to load in 5.2's Python 3.13; `numpy>=1.26` in the wheel metadata is a pip-time constraint only, and the module ran against Blender 4.3's numpy 1.24 without complaint (rust-numpy checks the C API at import). Not yet done, needed for the gate:

- Build and run `tests/blender/test_wheel.py` on Windows x64 and Linux x64 (CI job, `docs/PLAN.md` "CI and release"), and on macOS x64.
- Done 2026-10-17: the same wheel loads in Blender 5.2.2 LTS (Python 3.13.13, numpy 2.3.4); study kit solves in 0.55 s on the worker thread, cancels in 5 ms. The built zip installs and enables with `blender --command extension install-file -r user_default --enable`, and `lamda_core` then imports from the extension's `.local/lib/python3.13/site-packages`.
- The extension zip itself (`scripts/build_extension.py`) is phase 1 work; this spike only proves the wheel.
